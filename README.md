# Complement-OUD

A human-first investigation of complement-associated transcriptional changes in opioid use disorder (OUD), using public brain transcriptomic data.

We will first acquire, validate, and explore eligible **human** datasets. Mouse analyses are a possible downstream extension, guided by the strength and relevance of the human findings.

Complement-related RNA expression is not direct evidence of biochemical complement activation.

## Reproducibility

[Pixi](https://pixi.sh/) manages the computational environment. Dependencies and tasks will be added only as they become necessary.

```bash
pixi install
```

Work in progress: `architecture/refactor-v1`. Historical analyses remain available on `main`.

## Human data acquisition

The single acquisition entrypoint is `scripts/01a_download.py` (Python standard library only).

```bash
pixi run python scripts/01a_download.py --list
pixi run python scripts/01a_download.py
pixi run python scripts/01a_download.py --datasets GSE174409
```

The acquisition script covers all four human cohorts: GSE174409, GSE225158, GSE194368, and GSE240457. It records checksums under ignored `data/metadata/acquisition/`. The GSE194368 matrix uses NCBI's generated-count fallback and is missing GSM5834154 relative to GEO; do not silently substitute or combine count pipelines.

## Human metadata validation

After downloading and inspecting the original files, run the lightweight, permanent
study-design validation. It uses only the JSON reports already generated by the
temporary inspector and **does not load or alter expression matrices**.

```bash
# Temporary structural inspection, only if inspection JSON reports are missing
pixi run python scripts/_inspect_human_data.py

# Verify GSE225158 raw counts once (already validated locally)
pixi run python scripts/_inspect_human_data.py --reconcile-only --verify-h5ad-raw

# Permanent study-design validation; fast to rerun
pixi run python scripts/01b_validate_human.py
```

Results are written to `outputs/validation/human/`: 
`bulk_samples.csv`, `striatum_donor_region_samples.csv`,
`midbrain_libraries.csv`, `unresolved_issues.csv`, and
`dataset_readiness.json`. Outputs are ignored by Git and must be reviewed
before downstream QC or differential expression.

**Key design constraints:** GSE174409 and GSE225158 likely share 12 donors
(therefore are not independent biological replication); the GSE225158 processed
object has 22 of 24 donor–region libraries (two caudate libraries, C-612 and C-13291, were excluded by the authors after documented wetting failures and low-quality metrics; see [GSM7040228](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSM7040228) and [GSM7040229](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSM7040229)); GSE194368's NCBI matrix has 41 of
42 GEO samples; GSE240457's 27 H5 files are pooled libraries without a
verified public barcode-to-donor/diagnosis crosswalk. Preserve these uncertainties,
treat donors—not nuclei—as biological replicates, and do not use transformed
H5AD `.X` for count-based pseudobulk. Complement RNA levels do not directly
measure complement activation.

## Phase 2: QC planning (before filtering)

Begin with the [source provenance and QC-strategy audit](docs/02a_source_provenance_audit.md), then review the [human QC design and decision register](docs/02_human_qc_plan.md). Together they document dataset origins, assay layers and biological replication units, pre-filter diagnostics, candidate exclusions, and downstream consequences of major decisions. **No Phase 2 filtering or DE has been implemented or approved yet.** Review the acceptance gates before implementation.

## Phase 2a: read-only bulk QC

[Preflight specification](docs/02b_qc_preflight.md) defines inputs, metrics,
non-exclusion outlier flags and manuscript safeguards. Follow the
[source provenance audit](docs/02a_source_provenance_audit.md) and
[Phase 2 QC decision register](docs/02_human_qc_plan.md).

```bash
pixi run python -m unittest discover -s tests -p 'test_qc_bulk.py' -v
pixi run python scripts/02a_qc_bulk.py
```

This stage **does not filter, normalize, remove samples, calculate DE or modify
source data**. It writes `outputs/qc/human/bulk_sample_qc.csv` and
`outputs/qc/human/bulk_qc_readiness.json` with SHA-256 provenance. Existing
H5AD and midbrain 10x libraries are reserved for later assay-specific
read-only QC. Treat all robust-z flags as prompts for review, never automatic
exclusions.

## Phase 2b: unsupervised bulk diagnostics

This step uses **NumPy** for per-cohort PCA of the 2,000 highest-variance
log1p-CPM gene profiles, plus sample-wise Pearson correlations. The gene
selection is for visualization, **not an inferential gene filter**. It reads
and verifies the same unmodified source count files via the checksums from
Phase 2a. No samples are removed.

```bash
pixi install
pixi run python -m unittest discover -s tests -p 'test_qc_bulk*.py' -v
pixi run python scripts/02b_qc_bulk_multivariate.py
```

Outputs: `outputs/qc/human/bulk_pca_scores.csv`,
`bulk_sample_correlations.csv`, `bulk_pca_feature_selection.csv` and
`bulk_multivariate_readiness.json`.

**Mitochondrial fractions are intentionally unavailable by default.** A vetted
annotation table with `dataset,feature_id,gene_symbol,chromosome` can be
supplied with `--annotation-csv`, but any resulting fractions are provisional
until complete mitochondrial feature mapping is audited. Do not treat a partial
mapping as a quantitative QC metric.

**Repository hygiene:** Raw downloads, intermediate reports and generated QC
files remain in ignored `data/` and `outputs/`; the tracked repository
retains small code, unit tests and methods records. Do not delete raw source
files or acquisition/checksum manifests. The temporary inspector is kept until
its required evidence-extraction functions are replaced by tested permanent
code; cleanup must not make historical validation irreproducible.

## Phase 2c: bulk annotation and mitochondrial sensitivity

The [source-verification plan](docs/02a_source_provenance_audit.md) requires
real gene annotation references rather than guessing symbols from Ensembl or
numeric Entrez identifiers. The `02c` stage audits matching feature IDs,
identifies mitochondrial genes by reference chromosome, computes provisional
mitochondrial count fractions, and performs a **PCA-only** sensitivity excluding
mitochondrial genes. It does **not** change source counts or downstream DE
feature eligibility.

Download reference files to ignored `data/reference/` (do not commit them).
GENCODE v47 is a **modern lookup reference**; it is not established as the
original GSE174409 quantification annotation, and discrepancies must be
documented before downstream gene mapping. NCBI's `gene_info` is a changing
lookup snapshot, not the original GSE194368 count pipeline reference.

```bash
mkdir -p data/reference
curl -fL --retry 3 \
  https://ftp.ebi.ac.uk/pub/databases/gencode/Gencode_human/release_47/gencode.v47.annotation.gtf.gz \
  -o data/reference/gencode.v47.annotation.gtf.gz
curl -fL --retry 3 \
  https://ftp.ncbi.nlm.nih.gov/gene/DATA/GENE_INFO/Mammalia/Homo_sapiens.gene_info.gz \
  -o data/reference/Homo_sapiens.gene_info.gz
pixi run python -m unittest discover -s tests -p 'test_qc_bulk*.py' -v
pixi run python scripts/02c_qc_bulk_annotation.py \
  --gencode-gtf data/reference/gencode.v47.annotation.gtf.gz \
  --ncbi-gene-info data/reference/Homo_sapiens.gene_info.gz
```

Review `outputs/qc/human/bulk_feature_annotation_audit.csv`,
`bulk_mitochondrial_qc.csv`, `bulk_pca_mt_sensitivity.csv`, and
`bulk_annotation_readiness.json` before using any mitochondrial metrics for
QC decisions. The status intentionally remains **provisional** until full
reference/matrix feature coverage and source compatibility have been evaluated.
The script refuses mismatched count checksums and incompatible annotation
namespaces. Phase 2c requires no extra Python packages beyond existing NumPy.

## Phase 2d: GSE225158 inherited single-nucleus QC

The `02d` stage audits the **original author-retained nuclei**, without
re-filtering or opening the full sparse count matrix. It reads H5AD `obs`
annotations (donor, donor–region, diagnosis, cell type, inherited QC flags and
per-nucleus RNA counts/features) and reconciles them with the inspection and
`01b` GEO donor–region validation table.

```bash
pixi run python -m unittest discover -s tests -p 'test_qc_striatum.py' -v
pixi run python scripts/02d_qc_striatum.py
```

Outputs in ignored `outputs/qc/human/`: `striatum_donor_celltype_qc.csv`,
`striatum_inherited_flags.csv`, `striatum_donor_coverage.csv` and
`striatum_qc_readiness.json`. Flag values are *described*, not used to
exclude nuclei; the meaning of inherited QC flags must still be reconciled
with the original authors' methods. No pseudobulk, DE, or count modification.

The source is **gzip-compressed H5AD**; opening it requires temporary
decompression to about **8.8 GB** in the source-data folder. This stage checks
for at least **13 GB free** and removes its temporary copy automatically.
For an already decompressed local file, use `--h5ad PATH` instead. Do not
commit raw data, temporary copies, or generated QC outputs.

## Phase 2e: GSE240457 pooled midbrain 10x technical QC

The `02e` stage processes 27 Cell Ranger `filtered_feature_bc_matrix.h5`
libraries inside `GSE240457_RAW.tar`, validating each against the existing
inspection and `01b` library inventory. Libraries are **multiplexed donor
pools**, not independent donors. The script summarizes filtered barcode-level
Gene Expression UMI counts, detected features, and provisional `MT-`-named
gene fractions. No barcode or library is removed, no pooled library is
assigned a diagnosis, and donor-level DE remains blocked.

```bash
pixi run python -m unittest discover -s tests -p 'test_qc_midbrain.py' -v
pixi run python scripts/02e_qc_midbrain.py
```

Outputs in ignored `outputs/qc/human/`: `midbrain_library_qc.csv` and
`midbrain_qc_readiness.json`. The JSON records the input archive checksum,
all 27 per-library distributions, and explicit donor-mapping limitations.
`--max-libraries 2` supports a diagnostic partial run and clearly labels it
incomplete. Temporary extraction is limited to one 10x library at a time;
the source TAR and H5 files are never modified.

After reviewing both `02d` and `02e` outputs, conduct the planned
Phase 2-wide QC decision and code-consolidation review before Phase 3.
